## What this lab is

The cluster is the factory floor. Kubernetes schedules pods, mounts shared storage, and routes traffic. It does not know it is running federated learning.

The FL pipeline is a simulation: each trainer pod is a client with its own MNIST shard. The algorithm is federated; the data still lives on a shared PVC. The point of the lab is coordination mechanics, not phone-fleet logistics.

## How the pieces fit

```
Oracle VM Box
│
├── talos-cp-01       Control plane (API, etcd, scheduler)
├── talos-worker-01   Trainer client A
└── talos-worker-02   Trainer client B

What Kubernetes sees          What FL sees
─────────────────────         ─────────────────────
Deployment (replicas)     →   trainer clients
Job                       →   FedAvg aggregation
Service (ClusterIP)       →   Redis coordination bus
PVC (ReadWriteMany)       →   shared model checkpoints
```

Read **Part 1** first so the cluster is Ready, then deploy **Part 2**. Use **CNN vs Federated Learning** when you need a clean split between the model architecture and the training protocol.
